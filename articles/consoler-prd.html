# Consoler（肯受）产品需求文档（PRD） **版本**：V1.0 **日期**：2026年3月14日 **作者**：跨境王不二 **状态**：MVP阶段 --- ## 1. 项目概述 ### 1.1 产品名称 - **英文名**：Consoler（安慰者） - **中文名**：肯受 ### 1.2 产品定位 一个关于"被看见"的社会实验。让每个人在最难的时刻，都能被另一个人真正懂得。 ### 1.3 核心愿景 **让世界更美好，从被懂得开始。** ### 1.4 产品Slogan - "你可以不坚强" - "这里没有需要你扮演的人" - "被懂得，就是最好的药" --- ## 2. 用户画像 ### 2.1 目标用户 #### 2.1.1 "肯"者（诉说者） | 维度 | 描述 | |------|------| | **年龄段** | 16-40岁（MVP阶段聚焦20-35岁） | | **性别分布** | 男女均可，重点关注男性群体（心理求助羞耻感更强） | | **典型场景** | 职场压力、身体疾病、情感困扰、身份焦虑 | | **核心痛点** | - 戴着"没事"面具，情绪无处释放
- 对熟人说不出口，怕成为负担
- 心理咨询太贵/太麻烦
- 深夜情绪崩溃，无人可找 | | **现有解决方案** | 刷小红书焦虑自救、给AI聊天、网易云评论区、硬扛 | **用户故事（小林）**： > 28岁，互联网运营，轻度焦虑+偶发惊恐发作。KPI压力大，经常加班。去年开始突然心慌手麻，检查心脏没问题，医生说是焦虑引起的躯体症状。不敢跟爸妈说，朋友都很忙，心理咨询500块一小时负担不起。深夜给AI发过"我好难受"，但对着机器哭很 pathetic。 #### 2.1.2 "受"者（倾听者） | 维度 | 描述 | |------|------| | **年龄段** | 20-40岁 | | **核心动机** | - 有相似经历，想 helping
- 相信倾听本身就是一种治愈
- 纯粹利他，获得被需要感
- 心理学学生/从业者积累经验 | | **核心特质** | 愿意暴露自己的脆弱，更能接住他人的脆弱 | | **持续动力** | 帮助他人的快乐、双向治愈、等级认可 | --- ## 3. 核心功能 ### 3.1 功能清单 | 功能模块 | 功能点 | 优先级 | MVP版本 | |---------|--------|--------|---------| | **用户系统** | 注册/登录 | P0 | ✅ | | | 身份选择（肯/受） | P0 | ✅ | | | 个人标签/经历 | P0 | ✅ | | | 实名认证（受者） | P1 | ⭕ | | **匹配系统** | 标签匹配算法 | P0 | ✅ | | | 人工审核匹配 | P0 | ✅ | | | 实时在线匹配 | P1 | ⭕ | | **对话系统** | 文字聊天 | P0 | ✅ | | | 语音通话 | P1 | ⭕ | | | AI辅助提示 | P1 | ⭕ | | **安全系统** | 敏感词监控 | P0 | ✅ | | | 高危情况SOP | P0 | ✅ | | | 内容举报 | P0 | ✅ | | | 端到端加密 | P1 | ⭕ | | **运营系统** | 用户反馈 | P0 | ✅ | | | 受者等级体系 | P2 | ⭕ | | | 数据分析后台 | P2 | ⭕ | ### 3.2 功能详解 #### 3.2.1 身份选择机制 **首次登录流程**： ``` 用户进入 → 选择今日身份 → 【肯】或【受】 ``` **【肯】者入口**： - 选择倾诉主题标签（多选）：#职场压力 #身体疾病 #亲密关系 #原生家庭 #自我怀疑 - 简述当前状态（可选）："刚做完手术，卧床一个月" - 紧急程度：🔴 急需倾诉 / 🟡 偶尔低落 / 🟢 相对稳定 - 偏好形式：文字 / 语音 **【受】者入口**： - 填写经历标签（匹配依据） - 可倾听时间段 - 当前状态：开放匹配 / 暂时休息 - 通过"共情测试"（MVP后可加入） #### 3.2.2 匹配机制 **匹配算法 V1.0（MVP）**： ```python # 简化逻辑 def match(ken, shou): # 1. 标签匹配度 tag_match = intersection(ken.tags, shou.tags) # 2. 经历相似度（关键词匹配） experience_match = similarity(ken.experience, shou.experience) # 3. 紧急程度优先 if ken.urgency == "🔴": priority += 10 # 4. 在线状态 if shou.online: priority += 5 return sorted_candidates ``` **匹配原则**： - 红色用户（急需）→ 优先匹配有相似标签的在线受者 - 标签匹配不到 → 匹配高共情评分的通用受者 - 深夜无人在线 → AI接管，告知"真人明早回复" #### 3.2.3 对话机制 **对话前**： - 双方确认匹配（10秒内可拒绝） - 展示对方标签（不涉及具体身份） - 倒计时3秒后开始对话 **对话中**： - 时长限制：30-60分钟 - 受者端AI辅助（可选）：实时提示建议回应 - 敏感词实时监控 **对话后**： - 双方填写简短反馈（1-5星 + 标签评价） - 可选择"愿意再次匹配"（双向选择则建立固定关系） --- ## 4. 产品流程 ### 4.1 核心用户旅程 ``` 【肯者旅程】 情绪低落 → 打开App → 选择"肯" → 填写标签 → 等待匹配 → 开始对话 → 倾诉释放 → 结束对话 → 填写反馈 → 选择是否继续匹配 【受者旅程】 打开App → 选择"受" → 设置在线状态 → 等待匹配通知 → 接受匹配 → 倾听陪伴 → 结束对话 → 填写反馈 → 获得"被感谢"记录 ``` ### 4.2 关键流程图 #### 4.2.1 匹配流程 ``` ┌─────────────┐ │ 用户进入 │ └──────┬──────┘ ▼ ┌─────────────┐ │ 选择身份 │ │ 【肯】/【受】 │ └──────┬──────┘ ▼ ┌─────────────┐ ┌─────────────┐ │ 填写信息 │ │ 设置状态 │ │ 标签/经历 │ │ 在线/休息 │ └──────┬──────┘ └──────┬──────┘ │ │ ▼ ▼ ┌─────────────┐ ┌─────────────┐ │ 发起匹配 │────▶│ 等待请求 │ │ 系统匹配 │ │ 接收通知 │ └──────┬──────┘ └──────┬──────┘ │ │ └─────────┬─────────┘ ▼ ┌─────────────────┐ │ 匹配成功 │ │ 双方确认进入对话 │ └────────┬────────┘ ▼ ┌─────────────────┐ │ 开始对话 │ │ 30-60分钟陪伴 │ └────────┬────────┘ ▼ ┌─────────────────┐ │ 对话结束 │ │ 双方填反馈 │ └─────────────────┘ ``` #### 4.2.2 高危情况处理流程 ``` 对话进行中 │ ▼ AI监控检测到高危关键词 （自杀/自伤/伤害他人） │ ▼ ┌─────────────────┐ │ 1. AI立即介入 │ │ 发送危机干预话术 │ └────────┬────────┘ ▼ ┌─────────────────┐ │ 2. 触发人工审核 │ │ 后台值班人员接管 │ └────────┬────────┘ ▼ ┌─────────────────┐ │ 3. 高危确认 │ │ 保持对话不断 │ │ 专业支持已接入 │ └────────┬────────┘ ▼ ┌─────────────────┐ │ 4. 启动保护机制 │ │ 获取紧急联系人 │ │ 对接公安/急救 │ └─────────────────┘ ``` --- ## 5. 安全与风控 ### 5.1 隐私保护 | 层级 | 措施 | 说明 | |------|------|------| | **身份隔离** | 手机号-账号-昵称三层分离 | 即使数据库泄露也无法关联真实身份 | | **端到端加密** | 聊天内容加密传输 | 连平台都看不到内容（MVP后可实现） | | **阅后即焚** | 可选24小时后自动删除 | 减少用户担心被截图的顾虑 | | **截图防护** | App层面禁止截图 | 技术可行但需权衡用户体验 | ### 5.2 内容安全 **敏感词库**： - 高危词：自杀、自残、杀人、伤害等 - 不当建议词："那你去死啊"、"矫情"等 - 广告/引流词 **处理机制**： - 实时检测，0.5秒内响应 - 高危词立即触发人工审核 - 不当建议词提示受者修改 ### 5.3 受者质量把控 **准入机制**： 1. 实名认证（身份证+人脸识别） 2. 填写真实经历（人工审核） 3. 通过"共情测试"（MVP后可加入） 4. 签署保密协议 **退出机制**： - 用户投诉累计3次，暂停资格 - 被标记"不舒服"比例过高，降级处理 - 主动可申请休息（保护倾听者burnout） ### 5.4 高危情况SOP **定义**：涉及自杀、自伤、伤害他人的言论 **响应流程**： 1. **0-30秒**：AI检测并发送干预话术 2. **30秒-2分钟**：人工审核介入 3. **2分钟后**：如确认高危，启动保护机制 **保护机制**： - 对话保持，受者被告知"专业支持已接入" - 获取用户授权过的紧急联系人信息 - 如情况紧急，对接公安/急救系统 **用户协议明确**： > "当系统检测到您有伤害自己或他人的风险时，我们将启动保护机制，这可能涉及联系紧急服务。" --- ## 6. MVP方案 ### 6.1 MVP范围 **用最简单的方式验证核心假设**：陌生人之间匿名倾诉是否有价值？ **MVP形式**： - 不开发App，使用现有工具（微信/飞书/企业微信） - 人工匹配，而非算法 - 文字为主，暂不支持语音 - 核心流程跑通即可 ### 6.2 MVP用户规模 - **肯者**：10人 - **受者**：10人 - **实验周期**：2周（3月15日-31日） ### 6.3 MVP流程 ``` 【报名阶段】 - 通过公众号/朋友圈招募 - 填写报名表（Google表单/问卷星） - 人工筛选，确保多样性 【匹配阶段】 - 发起人（王老师）根据标签手动配对 - 双方确认时间和形式 【对话阶段】 - 使用微信/企业微信单聊 - 时长30-60分钟 - 发起人全程不参与，保护隐私 【反馈阶段】 - 双方填写反馈问卷 - 1-5星评分 + 开放式建议 - 是否愿意再次匹配 【复盘阶段】 - 分析反馈数据 - 提炼用户故事 - 决定下一步方向 ``` ### 6.4 MVP成功指标 | 指标 | 目标值 | 衡量方式 | |------|--------|---------| | 完成对话率 | >= 80% | 报名后实际完成对话的比例 | | 满意度 | >= 4.0/5 | 对话后双方评分均值 | | 再次匹配意愿 | >= 50% | 愿意继续匹配的用户比例 | | 安全事件 | 0 | 无重大安全投诉或危机 | | 留存率 | >= 60% | 实验期内完成2次以上对话 | --- ## 7. 技术架构 ### 7.1 MVP技术方案 **工具选择**： - **报名**：飞书多维表格 / 问卷星 - **匹配**：人工操作 - **对话**：企业微信/微信 - **反馈**：飞书多维表格 **零成本启动，验证需求后再开发产品** ### 7.2 产品技术架构（未来） ``` 前端：微信小程序 / React Native App 后端：Node.js / Go 数据库：PostgreSQL + Redis AI服务：Kimi / 自研NLP模型 部署：阿里云/腾讯云 ``` ### 7.3 关键算法 **匹配算法**： - 基于标签的向量相似度计算 - 考虑时间、紧急程度、历史匹配记录 **AI辅助**： - 敏感词检测：基于NLP的实时分类 - 情绪识别：对话情绪趋势分析 - 回应建议：基于共情模型的生成式建议 --- ## 8. 商业模式（远期） ### 8.1 暂不考虑的商业模式 MVP阶段**完全免费**，不考虑任何商业化。 ### 8.2 未来可能的模式 | 模式 | 说明 | 优先级 | |------|------|--------| | **企业EAP** | 向企业出售员工心理健康服务 | 高 | | **认证受者收费** | 持证心理咨询师提供专业服务 | 中 | | **公益基金** | 申请心理健康类公益基金 | 中 | | **数据服务** | 匿名化后的情绪趋势报告（To G/To B） | 低 | --- ## 9. 里程碑 ### 9.1 第一阶段：MVP验证（3月15日-4月15日） -
